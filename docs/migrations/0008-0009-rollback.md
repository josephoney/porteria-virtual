# Rollback notes — migrations 0008 and 0009

## Backup

Before applying:

```text
backups/porteria_pre_people.sql
```

## 0008 — people, accounts, assets and tenant profiles

Adds:

- people/accounts;
- assets;
- organization/community profile columns;
- memberships.person_id and location_unit_id;
- invitations.location_unit_id;
- NIT index and backfills from users.

Rollback order:

1. Keep a fresh `pg_dump`.
2. Drop FKs/indexes added by 0008.
3. Drop profile columns from communities/organizations.
4. Drop memberships.person_id, memberships.location_unit_id, invitations.location_unit_id.
5. Drop assets, accounts and people.
6. Restore `backups/porteria_pre_people.sql` if data must be restored.

Do not drop `users`; it remains the compatibility path.

## 0009 — person/account references

Adds:

- visitors.created_by_person_id;
- calls.operator_person_id;
- events.actor_person_id;
- access_codes.created_by_person_id;
- guard_rounds.guard_person_id;
- refresh_tokens.account_id.

Rollback:

1. Drop the new columns and their FKs.
2. Keep legacy `created_by`, `operator_id`, `actor_id`, `guard_id` and `user_id` columns.
3. Restore the pre-migration backup if audit history must be recreated.
